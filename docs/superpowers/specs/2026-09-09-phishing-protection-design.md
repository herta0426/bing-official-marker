# Bing 官网标记脚本分级防护设计

## 目标

降低用户从 Bing 搜索结果误点到银狐伪造站点的概率，同时避免脚本用“官方”标签制造过强的安全感。脚本仍以百度搜索结果中的“官方”标记作为参考信号，但不把该信号视为绝对安全证明。

## 防护等级

1. **可信参考**：目标 URL 使用 HTTPS，协议和主机名经过标准化，且与百度认证 URL 的主机名完全一致。显示“官网参考”，允许正常点击。
2. **需要确认**：目标使用 HTTPS，与认证 URL 的可注册域相同但主机名不同，且不属于公共后缀租户误匹配。显示“需确认”，点击时展示目标域名和认证域名，用户确认后打开。
3. **高风险**：HTTP、IP 地址、异常端口、URL 用户信息、短链或显式跳转、无法可靠提取/解析的 URL，以及公共后缀下仅子域相同的 URL。显示风险提示，默认阻止点击，用户确认后才打开。

## 数据流

从百度结果提取认证 URL后，使用 `URL` 解析并只接受 `http:`/`https:`。去除默认端口、尾随点和大小写差异后进行去重与匹配。Bing 只读取结果标题区域的主链接。所有插入 DOM 的节点使用脚本专属 `data-bom-*` 标记，清理时不触碰其他脚本节点。

## 网络与状态

百度请求仅允许访问明确的百度搜索域名，不发送用户 Cookie 或伪造 User-Agent。请求增加超时处理和短期 `sessionStorage` 缓存。每次搜索使用请求序号校验，旧请求返回时不得修改当前页面。URL 变化和动态结果监听需要节流，避免持续扫描整个页面造成高开销。

## 点击行为

脚本不修改可信结果的目标地址。对需要确认或高风险的结果使用捕获阶段点击处理，阻止默认导航并弹出确认框；确认内容包含目标 URL、认证 URL（如有）和风险原因。插入的百度认证参考结果明确标注来源，不伪装成 Bing 原生结果。

## 验证

增加可在 Node.js 中运行的纯逻辑测试，覆盖 HTTPS 严格匹配、子域确认、公共后缀、IP、异常端口、短链、显式跳转、编码 URL、重复注入和旧请求结果。完成后运行测试、语法检查，并检查用户脚本元数据权限范围。

## 已知限制

域名一致不能证明站点没有被入侵，百度认证数据也可能过期或错误。脚本无法可靠判断页面内容、最终登录跳转或第三方支付流程，因此界面文案必须使用“参考”而不是绝对安全承诺。
